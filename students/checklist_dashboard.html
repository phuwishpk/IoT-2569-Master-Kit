ระบบนิเวศไอโอทีแบบบูรณาการ 4 โปรโตคอล • ESP32 Hardware + Kestrel .NET 8 Gateway + Flutter Mobile + Web Command Center

สัปดาห์ที่ 13 (The Grand Finale)
🌐 แผนผังสถาปัตยกรรม 4 โปรโตคอล (Ecosystem Topology): 🔍 เปิด SVG ความละเอียดสูง ↗️
🔍 คลิกเพื่อดูผังสถาปัตยกรรมขนาดใหญ่
🔌 การเชื่อมต่อฮาร์ดแวร์จริง (ใช้วงจรที่ 7 + สาย USB-UART เข้า PC): 🔍 ดูรูปถ่ายจริง ↗️
🔍 คลิกเพื่อดูภาพถ่ายอุปกรณ์จริง
📌 การเชื่อมต่อฮาร์ดแวร์ในสัปดาห์ที่ 13 (ใช้วงจรที่ 7 ซ้ำ):
• ขา 3V3 (ซ้ายแถว 1): จ่ายไฟเลี้ยง 3.3V เข้าขา 1 ของ Potentiometer 10k
• ขา GPIO 34 (ซ้ายแถว 5): รับสัญญาณแอนะล็อก ADC1_CH6 จากขากลาง Wiper POT
• ขา GND (ซ้ายแถว 14 & ขวาแถว 1): กราวด์ร่วมของ POT และหลอดไฟ LED
• ขา GPIO 2 (ขวาแถว 14): ผ่าน R 220Ω เข้า LED Anode (+) รับคำสั่งเปิด-ปิดไฟ
• สาย USB Data Cable: เสียบเข้าพอร์ต PC เพื่อสตรีมข้อมูล Serial (115200 bps) เข้าเกตเวย์ Kestrel
⚡ สะพานเชื่อม 4 โปรโตคอล (Multi-Protocol Bridge):
1. Hardware Serial (UART): ดักรับข้อมูลสตรีมดิบจากบอร์ด ESP32 ด้วย BackgroundService (< 1ms)
2. Embedded MQTT Broker (พอร์ต 1883): กระจายข้อมูลเซนเซอร์เข้า Topic iot/{ID}/telemetry (2-10ms)
3. RESTful Minimal API (พอร์ต 5001): ให้บริการ GET /api/telemetry และ POST /api/led/on (10-50ms)
4. Realtime SignalR Hub: ผลักดันข้อมูลขึ้นเว็บแดชบอร์ดสดๆ ผ่าน WebSockets (1-5ms)
ฮาร์ดแวร์: NodeMCU-32S (38 Pins) • Kestrel Web & Protocol Engine (.NET 8)

ESP-IDF Environment หาไม่เจอ / idf.py: command not found

⚡ ESP-IDF Toolchain
🚨 ข้อความ Error ที่พบ: Windows: The term 'idf.py' is not recognized as the name of a cmdlet, function, or operable program. macOS / Linux: zsh: command not found: idf.py หรือ bash: idf.py: command not found

💡 สาเหตุ: คุณกำลังเปิด Terminal ทั่วไปที่ยังไม่ได้โหลดชุดตัวแปร PATH ของ ESP-IDF เข้าสู่เซสชัน

🪟 วิธีแก้บน Windows (PowerShell / CMD)

วิธีดีที่สุด: เปิดโปรแกรม ESP-IDF 5.x PowerShell จาก Start Menu หรือรันสคริปต์ export:

& "$env:USERPROFILE\esp\esp-idf\export.ps1"
# หรือหากลงที่ Espressif:
& "C:\Espressiframeworks\esp-idf-v5.3\export.ps1"
🍎🐧 วิธีแก้บน macOS / Linux (Terminal)

รัน export หรือเพิ่ม alias คำสั่ง get_idf ให้เรียกใช้ง่ายตลอดไป:

. $HOME/esp/esp-idf/export.sh
# หรือสร้าง shortcut ถาวรใน ~/.zshrc:
echo 'alias get_idf=". $HOME/esp/esp-idf/export.sh"' >> ~/.zshrc && source ~/.zshrc
get_idf
✅ ตรวจสอบผล: idf.py --version (ต้องแสดง ESP-IDF v5.x.x)

🔌 พอร์ต USB / Drivers

ls /dev/cu.usbserial* /dev/cu.SLAB* 2>/dev/null

# Linux:
sudo usermod -a -G dialout $USER && newgrp dialout

แฟลชไม่เข้า ค้าง `Connecting........_____.....` Timeout

⚡ Flashing / Hardware Boot
🚨 ข้อความ Error ที่พบ: Connecting........_____....._____....._____..... A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header
👉 วิธีกดปุ่มบังคับบอร์ดเข้า Download Mode (แก้ได้ 100%):
  1. กดรันคำสั่งแฟลชตามปกติ: idf.py -p <PORT> flash monitor
  2. ทันทีที่ Terminal แสดงจุด Connecting........ ให้ใช้ปลายนิ้ว กดปุ่ม `BOOT` (หรือ `IO0`) บนบอร์ดค้างไว้ 1-2 วินาที แล้วปล่อย
  3. Terminal จะตรวจพบชิปทันทีและเริ่มเขียนข้อมูลลงชิป (Writing at 0x00010000...)
ลด Baud Rate หรือล้างชิปเมื่อเกิดข้อผิดพลาดในการเขียน: 
# ลดความเร็ว Baud Rate เพื่อให้สาย USB เสถียรขึ้น:
idf.py -p <PORT> -b 115200 flash monitor

# สั่งล้าง Flash ทั้งชิปเพื่อลบค่าขยะ:
idf.py -p <PORT> erase-flash

แฟลชผ่านแต่บอร์ดรีสตาร์ทวนลูป / Guru Meditation Error / Brownout Detector

⚡ Runtime Firmware Crash
🚨 ข้อความ Error ที่พบ: Guru Meditation Error: Core 0 panic'ed (LoadProhibited) หรือ Brownout detector was triggered rst:0x10 (RTCWDT_RTC_RESET) รีบูตซ้ำทุก 2 วินาที

# 3. ล้าง Flash และเบิร์นใหม่:
idf.py -p <PORT> erase-flash
idf.py -p <PORT> flash monitor

สิทธิ์เปิดพอร์ตบน Linux ถูกปฏิเสธ (Permission denied: '/dev/ttyUSB0')

🐧 Linux Serial Permissions
คำสั่งให้สิทธิ์ User ถาวรบน Ubuntu / Linux: 
# 1. เพิ่ม User ปัจจุบันเข้ากลุ่ม dialout
sudo usermod -a -G dialout $USER

# 2. ปรับสิทธิ์พอร์ตชั่วคราวให้เขียนได้ทันที
sudo chmod 666 /dev/ttyUSB0 /dev/ttyACM0 2>/dev/null || true

# 3. โหลดสิทธิ์ใหม่ (หรือ Logout แล้ว Login ใหม่)
newgrp dialout
